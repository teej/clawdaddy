# Expressive Acknowledgment Layer — Research

## Problem

When the user speaks, there's a 2-10 second delay before the backend delivers the real answer. During that gap we show a short acknowledgment generated by an on-device LLM (Apple Foundation Models) to make the interaction feel conversational. The ack must match the **type** of input — a compliance marker like "Roger." works for commands but feels wrong for questions like "What's your name?"

## Linguistics Background: Backchannel Cues

Victor Yngve (1970) identified that conversations run on two simultaneous channels: the main channel (speaker) and the backchannel (listener). Backchannel cues are short signals that say "I'm here, I heard you" without taking the conversational floor.

Functional types of backchannel cues:

| Type | Purpose | Examples |
|---|---|---|
| Continuers | "Keep going" | "Uh-huh", "Mm-hm" |
| Acknowledgments | "I understand" | "Right", "Okay", "Got it" |
| Newsmarkers | "That's noteworthy" | "Oh!", "Really?" |
| Assessments | "I have an opinion on that" | "That's great", "Interesting" |
| Change-of-activity | "Let's shift" | "So...", "Anyway..." |

The critical finding: **the appropriate backchannel depends on the speech act type of the user's utterance.** Questions get thinking markers, commands get compliance markers, statements get receipt markers.

## Speech Act Classification (Searle)

John Searle's speech act theory gives us the taxonomy we need:

1. **Directives — Commands** ("Set a timer", "Do the thing"): listener responds with compliance markers — "On it", "Got it", "Roger"
2. **Directives — Info Questions** ("What time is it?", "What's your name?"): listener responds with thinking markers — "Hmm", "Let me check", "Good question"
3. **Directives — Opinion Questions** ("What do you think about X?"): listener responds with deliberation markers — "Let me think", "That's a good one"
4. **Expressives** ("Hello", "Good morning"): listener responds with reciprocal greetings — already handled by existing greeting system
5. **Assertives — Statements** ("I had a good day", "The weather is nice"): listener responds with receipt/assessment markers — "I hear you", "Noted", "Nice"

## Industry Patterns

- **Amazon Alexa**: Progressive Response API sends up to 5 interim TTS messages during processing. Brief Mode replaces verbal confirmations with earcon chimes for simple commands. For home automation: just "Okay."
- **Google Assistant**: Conversation Design Guidelines define acknowledgments as a first-class component. Three levels: implicit confirmation (echo + continue), explicit confirmation (verify), no confirmation (self-evident).
- **Twilio**: Each additional second of latency reduces satisfaction 16%. Principle: "the goal isn't instant completion, it's instant acknowledgment."

The universal pattern: **acknowledge immediately (< 500ms), then deliver the full answer when ready.**

## Curated Acknowledgment Pools by Category

### A. Info Questions ("What time is it?", "What's your name?", "How does X work?")

Thinking markers — signal "I heard you and I'm retrieving the answer."

- Let me check.
- Hmm.
- Good question.
- Let me see.
- One sec.
- Checking.

### B. Opinion Questions ("What do you think?", "Should I do X?")

Deliberation markers — signal "I'm forming my view."

- Let me think.
- Good question.
- That's a good one.
- Hmm, interesting.

### C. Commands / Requests ("Set a timer", "Do the thing", "Turn it off")

Compliance markers — signal "received and executing."

- Copy.
- On it.
- Got it.
- Roger.
- Aye aye.
- Right away.

### D. Statements / Facts ("I had a good day", "The weather is nice")

Receipt markers — signal "I heard you and I care."

- I hear you.
- Noted.
- Ah, right.
- Nice.
- Got it.

## Classification Heuristics

Rule-based classification using simple heuristics achieves ~85-90% accuracy:

1. **Question**: contains `?`, or starts with wh-word (what/how/why/when/where/who/which), or starts with auxiliary verb (is/are/do/does/did/can/could/would/should/will)
2. **Opinion sub-question**: is a question AND contains opinion markers (think, opinion, feel, believe, recommend, suggest, prefer, "should I", "would you")
3. **Command**: starts with imperative verb (set, turn, make, do, run, start, stop, open, close, show, tell, find, get, give, send, play, create, delete, add, remove, help)
4. **Greeting**: already handled by existing system
5. **Statement**: fallback for anything else

## LLM Prompt Strategy

The on-device LLM struggles with open-ended generation and complex multi-step instructions. Key findings:

- **One-shot pick from a constrained list** is the most reliable prompt pattern for small models
- **Pre-classifying** the input type and passing only the relevant pool dramatically reduces the LLM's task complexity
- The prompt should frame it as a selection task, not a generation task

Recommended prompt structure per category:

```
[For info questions]
Pick the best acknowledgment for this message from the list: Let me check, Hmm, Good question, Let me see, One sec, Checking.
Reply with ONLY your pick and a period. Nothing else.

[For commands]
Pick the best acknowledgment for this message from the list: Copy, On it, Got it, Roger, Aye aye, Right away.
Reply with ONLY your pick and a period. Nothing else.
```

This turns an unreliable generation problem into a reliable constrained selection.

## Architecture

```
User input
    |
    v
[Rule-based classifier] — instant, deterministic
    |
    +---> QUESTION_INFO    --> LLM picks from thinking-marker pool
    +---> QUESTION_OPINION --> LLM picks from deliberation-marker pool
    +---> COMMAND          --> LLM picks from compliance-marker pool
    +---> STATEMENT        --> LLM picks from receipt-marker pool
    +---> GREETING         --> existing greeting system (no LLM)
    |
    v
[Fallback]: if LLM fails/times out, random pick from same pool
```
